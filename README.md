# Token查询

macOS 菜单栏常驻的 API 余额监控工具。余额挂在顶部菜单栏，点开是完整面板。

当前版本 **v1.10**。

---

## v1.10 更新（去掉独立的 Codex 页签）

Codex 额度上一版已经并进「总览」，那个单独页签就只剩重复了，这一版把它去掉。**页签里的信息没有丢**，全部折进了总览的 Codex 卡片。

- **页签从 5 个减到 4 个**：总览 / 趋势 / 账号 / 设置。Codex 额度现在只在总览里看。
- **折进总览的内容**（都按需出现，常见情况下不会变成噪音）：
  - **多窗口明细** —— 主指标只反映最紧张的那个窗口，第二个窗口单独列一行（`7 天窗口` … `已用 60% · 剩余 40%`）
  - **额外额度** —— 有值才显示（`不限量` 或 `$12.50`）
  - **免费版说明** —— 熔断且是 free 套餐时提示「免费版没有额外额度可买，只能等重置」
  - **凭据到期日** —— 粘贴 token 的账号只有约 10 天有效期，这个日期是刚需
  - **接口声明** —— `Codex 非官方接口，改版后可能失效。`
- **本机装了 Codex 但没加进账号列表时**，总览会显示一行「检测到本机已登录 Codex」+ 一个「导入」按钮（原来是页签里的空状态）。
- **重置时间带上窗口长度**：`1 个月窗口 · 10月15日 04:30 重置（还有 26 天 19 小时）`，否则「重置」没有时间尺度。
- **面板内容区高度 372 → 480**，让总览的两块（含上面这些细节）在常见情况下不用滚动。
- 顺带修掉一处视觉误导：额度剩余为 0 时，进度条原本还画 3pt 的红色小段，看起来像「还剩一点点」，现在 0% 就是空槽。
- **清掉两处会把人指去不存在的页签的文案**：趋势页选中 Codex 账号时的空状态原来写「额度信息请到「Codex」页签查看」，改成「请在「总览」里查看」；Codex 未安装时的建议原来写「这个页签会自动出现」，改成指引回总览点「导入」。

## v1.9 更新（总览页并入 Codex 额度）

之前「总览」只显示**当前选中账号**的详情 —— 选中 DeepSeek 就看不到 Codex，反之亦然。这一版把它改成按服务商并列的概览，两边的额度同屏可见，各自带独立的「实时查询」按钮。

- **总览页改成两个常驻区块**：上方「DeepSeek 余额」，下方「Codex 额度」。不用再切账号才能看到另一边。
- **Codex 区块**：每个已启用的 Codex 账号一张紧凑卡片 —— 账号名、套餐徽章（如 `FREE`）、剩余百分比、额度条、重置时刻。多个 Codex 账号会全部列出，各自独立刷新。
- **每个区块各有自己的「实时查询」按钮**：只查那一个账号，互不影响。（之前共用一个状态，会变成点其中一个、另一个也跟着转。）查询期间按钮转圈并禁用，且保证至少转满一圈。
- **「选中账号」的作用收窄**：现在只影响菜单栏的「当前账号」模式、趋势页，以及有多个 DeepSeek 账号时总览展示哪一个。Codex 始终全部展示。
- **面板内容区高度 336 → 372**，让 DeepSeek + Codex 两块在常见情况下不用滚动就能看全。
- 顺手修掉一处文案不一致：Codex 数据过期时（有旧值但本次刷新失败），标题原本显示的是错误原因，现在和 DeepSeek 区块一致，显示「额度可能已过期」。

## v1.8 更新（多 Codex 账号 + 菜单栏显示 Codex）

之前 Codex 只能看本机那一个登录，账号列表里也没有它。这一版把它变成了和 DeepSeek 平级的账号类型。

- **Codex 成为一等账号**：在「账号」页点「添加账号」，把服务商切换成 **Codex** 即可。账号列表、启用/停用、预警线、右键菜单全部通用。
- **首次启动自动导入**：检测到本机 `~/.codex/auth.json` 时，会自动加一个「Codex（本机）」账号，**不需要你手动操作**。删掉之后不会再自己冒出来。
- **支持多个 Codex 账号**，两种凭据来源：

  | 方式 | 做法 | 有效期 |
  |---|---|---|
  | **读取 auth.json**（推荐） | 每个账号指向一个 `auth.json` 路径。第二个账号用另一个 `CODEX_HOME` 登录一次：<br>`CODEX_HOME=~/.codex-work codex login`<br>然后把 `~/.codex-work/auth.json` 填进去 | **长期**，Codex 自己续期 |
  | **粘贴 access_token** | 直接粘一个 token，可选填 account id | 约 **10 天**，到期需重新粘 |

  > 本程序**刻意不自动续期**：Codex 的 `refresh_token` 是轮换的，刷新后必须写回 `auth.json`，写错会破坏你自己的 Codex 登录。所以只有「让 Codex 自己维护」的方式才能长期有效。

- **菜单栏并排显示**：形如 `¥100.00 · CX 0%`。DeepSeek 给金额（`当前账号` 模式看选中账号，`合计` 模式看全部），Codex 始终给**最低的剩余百分比**（最紧张的那个才是真正的约束）。颜色取两者中更严重的。

- **总览页按类型显示**：选中 Codex 账号时显示剩余百分比、额度窗口、重置时间、「额度已用完」横幅；金额类指标（充值/赠送/今日消耗/本月消耗）和消耗趋势自动隐藏 —— Codex 接口不提供用量明细，画不出曲线。趋势页对 Codex 账号会明确说明这一点。

- **预警线单位跟着服务商变**：DeepSeek 是元，Codex 是剩余百分比（新建默认 20%）。

- **修掉一个数据安全隐患**：`AccountStore.load()` 原来在 JSON 解码失败时**静默返回空数组** —— 也就是只要有一个字段解不出来（例如新版本加了非可选字段而你的 `accounts.json` 是旧版写的），你的账号列表会全部消失且没有任何提示。现在会留日志、把坏文件备份成 `accounts.json.broken`，并且所有新增字段一律声明为 Optional 以保证向后兼容。

**加第二个 Codex 账号的完整步骤**：

```bash
# 1. 用另一个 CODEX_HOME 登录第二个账号
CODEX_HOME=~/.codex-work codex login

# 2. 在 Token查询 →「账号」→「添加账号」
#    服务商选 Codex → 凭据来源选「读取 auth.json」
#    路径填 ~/.codex-work/auth.json
```

## v1.7 更新（Codex 额度「已用完」状态）

第一次用真实数据打通 Codex 接口后发现的缺口：接口在额度耗尽时会回 `rate_limit.limit_reached: true`，**但百分比不一定到 100** —— 服务端可能提前熔断。原来的解析器完全没读这个字段，界面只看百分比，于是会出现「显示 12% 剩余、实际已经被拒绝」的误导。

- **新增「额度已用完」横幅**：读 `limit_reached`（新命名）与 `allowed` 取反（老命名）两个信号，任一成立即触发。横幅给的是**重置时刻**（`10月11日 11:41 重置（还有 26 天 20 小时）`），不是空话。免费版会额外说明「没有额外额度可买，只能等重置」。
- **窗口卡片**：剩余为 0 时右侧由「已用 100.0%」改为「已用完」。
- **重置时间支持 `reset_after_seconds`**：这是**相对现在的秒数**，而 `reset_at`/`resets_at` 是绝对时间。原来只读绝对时间，只给相对秒数的响应会显示「重置时间未知」。现在绝对时间优先（不会随请求时刻漂移），缺失时用相对秒数兜底。

实测你当前的账号状态：`plan_type: free`、`used_percent: 100`、`limit_reached: true`、重置于 **2026-10-11 11:41**。

## v1.6 更新（新增 Codex 页签）

- **新增「Codex」页签**：显示 ChatGPT 订阅下 Codex 的额度消耗（剩余百分比、窗口长度、重置时间、额外额度）。凭据直接复用 Codex 自己的 `~/.codex/auth.json`，**不需要在本程序里再登录一次**。没装 Codex 时这个页签会自动隐藏。

  **数据来源**：`GET https://chatgpt.com/backend-api/wham/usage`，请求头带 `Authorization: Bearer <access_token>` 和 `ChatGPT-Account-Id`。

  > ⚠️ 这是 Codex 桌面版自己在用的后端接口，**不是 OpenAI 公开文档里的 API**，改版后可能变化。字段命名在版本间变过（`primary_window`/`limit_window_seconds` 与 `primary`/`window_minutes` 两套都见过），所以解析器两套都认。

  **本程序刻意不刷新 token**：Codex 的 `refresh_token` 是轮换的，刷新后必须写回 `auth.json`，写错会破坏你自己的 Codex 登录。凭据过期时只提示你打开一次 Codex（它会自动续期），再回来刷新。

  **要看到数字，三个前提都得满足**：
  1. 装过 Codex 并且用 **ChatGPT 账号**登录（API Key 方式没有订阅额度可读）
  2. 网络能访问 `chatgpt.com`（国内直连不通，需要代理）
  3. ChatGPT 是付费套餐 —— **free 套餐几乎没有 Codex 额度**

  任何一个不满足，页签里都会写明是哪一个、以及下一步该做什么，不会只丢一个转圈。

  **注意**：Codex 被配置成走别的服务商时（例如 `config.toml` 里 `model_provider = "deepseek"`），它消耗的是那家的余额，**不消耗 OpenAI 的 Codex 额度**，这个页签自然也不会有变化。

## v1.5 更新（存储方式变更）

- **API Key 不再存进系统钥匙串，改为本机加密文件。** 之前每次启动都会弹窗要密码，原因是钥匙串条目的访问控制绑定的是**创建它的那个程序的代码签名标识**，而本项目用 ad-hoc 签名（签名标识就是二进制哈希），每重新编译一次哈希就变，系统就认为「这不是原来那个程序」→ 每次都问密码。现在改成存到本机数据目录，**不会再弹密码框**。

  存储位置：`~/Library/Application Support/Token查询/credentials.json`

  加密方式：AES-GCM，密钥由本机 `IOPlatformUUID` 经 HKDF-SHA256 派生（salt 单独存在 `credentials.vault.json`），文件权限 600。

  **安全性是明确下降的，这点必须说清：**

  | | 钥匙串（旧） | 加密文件（新） |
  |---|---|---|
  | 本机其他程序偷读 | 挡得住 | **挡不住**（它也能读到 IOPlatformUUID） |
  | 文件被拷到别的机器 | — | 挡得住，是一堆乱码 |
  | 云盘同步 / 备份 / 误发 | — | 挡得住 |
  | 弹密码框 | 每次都弹 | 不弹 |

  换来的是安静，代价是防不住本机恶意程序。这个取舍是知情的。

  **两个后果**：换机器或换主板后密钥派生源变了，解不开，需要重新填入 Key；`credentials.json` 或 `credentials.vault.json` 被删掉也一样。这两种情况下账号会标成「需重新填入 Key」，不会静默失效。

- **升级会自动迁移。** 首次启动新版本时会读一次钥匙串把已有 Key 搬进新存储（**这是最后一次弹密码框**），成功后清掉钥匙串里的旧条目。如果你在授权框点了取消，对应的账号会被标成「需重新填入 Key」，到「账号」页重新粘一次即可，账号、预警线、余额历史都不受影响。
- **设置页新增「凭据」区块**：显示存储方式、文件路径，可一键在访达中定位，也可清空本地全部 Key（带二次确认）。
- 顺带把三处重复的数据目录拼接统一到 `AppPaths`，并给所有数据文件收紧到 600 权限。

## v1.4 更新

- **修复：菜单栏图标现在有颜色了。** 之前只靠图标形状区分状态，颜色是丢的 —— 因为 macOS 会把菜单栏标签当**模板图**处理，只取 alpha、把颜色抹掉。现在把 SF Symbol 先画进自建 `NSImage`、用 `sourceAtop` 上色、再关掉 `isTemplate`，颜色就能保住。

  | 颜色 | 含义 |
  |---|---|
  | 绿色 `$` | 正常 |
  | 黄色 `⚠` | 余额低于预警线 |
  | 红色 `!` | Key 无效或网络异常 |

  余额数字也跟着变色，一眼能看出状态。加载态刻意不上色，留成系统模板图，这样浅色/深色菜单栏都能看清。

- **修复：实时查询的旋转动画不再被截断。** 之前用 `rotationEffect` + `repeatForever`，查询一快（通常几十毫秒）动画就被打断，看着像转到一半卡住。现在改成按真实时间算角度，并且**保证至少转满一圈**才停 —— 查得再快也能看到完整的旋转反馈。

## v1.2 更新（重要修复）

- **修复：账号编辑窗口打不进字。** 之前「添加账号 / 编辑账号」是用 `.sheet` 弹出来的。但菜单栏面板一旦失去焦点就会自动收起，而弹 sheet 正好会夺走面板的焦点 —— 面板被关掉，编辑器成了孤儿窗口，输入框点得中但敲不进字，预警线也改不动。
  现在编辑器**直接内联在面板里**，不再开新窗口。这也顺带解决了另一个问题：原来的弹窗宽 380px，而面板只有 322px，本身就装不下。

- 编辑器的「测试连接」移到独立一行，窄面板下不再和输入框挤在一起。
- 新增诊断日志：打开/关闭编辑器、测试连接结果、提交账号都会记到 `debug.log`。

## 安装

提供三种格式，任选其一：

| 文件 | 适合场景 | 安装方式 |
|---|---|---|
| **`Token查询-1.10.dmg`** | 分发、分享给别人（Mac 最主流） | 双击打开，把 App 拖进「应用程序」 |
| **`Token查询-1.10.pkg`** | 标准安装向导 | 双击，一路「继续」，自动装到「应用程序」 |
| **`Token查询.app`** | 本机快速使用 | 直接拖进「应用程序」 |

### 方式一：dmg（推荐）

1. 双击 `Token查询-1.10.dmg`，弹出磁盘映像窗口
2. 把左边的「Token查询」图标**拖进右边的「应用程序」文件夹**
3. 在访达侧边栏点磁盘映像旁的 ⏏ 推出

### 方式二：pkg

1. 双击 `Token查询-1.10.pkg`
2. 一路「继续」→「安装」，需要输入管理员密码
3. 自动装到「应用程序」

### 方式三：直接用 .app

把 `Token查询.app` 拖进「应用程序」文件夹，效果一样。

> **首次打开**：App 没做 Apple 开发者签名，需要到「应用程序」里**右键**点 Token查询 →「打开」→ 弹窗里再点一次「打开」。之后双击就正常了。
> 打开后不会出现在 Dock，只在顶部菜单栏显示。

## 配置 API Key

1. 点菜单栏上的图标
2. 切到「账号」页 →「添加账号」
3. 填入 DeepSeek API Key（在 [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys) 获取）
4. 点「测试连接」确认 Key 可用（可选，但建议）
5. 可选：起个备注名、设置低余额预警线
6. 可以重复添加多个 Key，各自独立显示余额和预警

Key 用 AES-GCM 加密保存在本机数据目录（`~/Library/Application Support/Token查询/credentials.json`），不再使用系统钥匙串，所以启动时不会弹密码框。详见上面的 v1.5 更新说明。

## 界面说明

菜单栏直接显示余额数字，图标颜色代表状态：

| 颜色 | 含义 |
|---|---|
| 绿色 `$` | 正常 |
| 黄色 `⚠` | 余额低于预警线 |
| 红色 `!` | Key 无效或网络异常 |

点开后四个页签：

| 页签 | 内容 |
|---|---|
| **总览** | 按服务商并列：上方 DeepSeek 余额（充值/赠送明细、今日与本月消耗、预估可用天数、近 7 天迷你趋势），下方 Codex 额度（剩余百分比、额度条、窗口长度 + 重置时刻，多窗口 / 额外额度 / 凭据到期按需显示）。两块各带独立的「实时查询」按钮；多个账号时还会显示各自的合计 / 账号数 |
| **趋势** | 7 天 / 30 天消耗柱状图、区间合计、日均消耗、预估可用天数 |
| **账号** | 管理多个 API Key。**右键**账号可编辑、停用、删除 |
| **设置** | 刷新间隔、菜单栏显示方式、默认预警线、开机自启、凭据存储、数据位置 |

## 消耗趋势是怎么算出来的

DeepSeek 官方只开放了**余额**接口，**没有**用量统计接口。

所以这里的「消耗」是本机记录余额快照后推算的：每隔一段时间记一次余额，用前后两次的差值算出这段时间花了多少。

这意味着：

- 刷新间隔越短，曲线越准（默认 5 分钟）
- 两次刷新之间的集中消耗会被平摊进区间
- 当天有充值会被记为 0 消耗，不会出现负值
- **它不是官方账单**，是给自己对账用的参考

所有数据存在 `~/Library/Application Support/Token查询/`，不上传任何地方。快照自动保留最近 90 天。

## 常见问题

**菜单栏没东西？**
App 没有 Dock 图标。打开「活动监视器」搜 `TokenMonitor` 确认在运行。

**余额显示 `!`？**
Key 无效或网络不通。到「账号」页右键 →「编辑…」重新填 Key，可以用「测试连接」先验证。

**金额变灰了？**
最近一次刷新失败，显示的是上一次成功的余额。鼠标悬停或等下一次自动刷新即可恢复。

**想清空历史趋势？**
设置页 →「数据」→「清空当前账号历史」或「清空全部历史数据」。

**升级后启动时弹了一次密码框？**
那是 v1.5 的一次性迁移：要把旧版存在钥匙串里的 Key 读出来搬进新存储。读钥匙串必须经系统授权，**这是最后一次**。点取消也没关系，账号会被标成「需重新填入 Key」，重新粘一次即可。

**账号旁边写着「需重新填入 Key」？**
说明凭据文件里没有可用的 Key，且这个账号以前是有 Key 的。常见原因：迁移时点了取消、换过机器或主板（密钥派生源变了）、`credentials.json` 或 `credentials.vault.json` 被删。到「账号」页右键 →「编辑…」重新粘一次即可，余额历史不受影响。

**换电脑了，Key 还在吗？**
不在。密文绑定本机硬件，换机后解不开，需要重新填入。这是加密的必然代价，不是 bug。

**重新打包：**

```bash
bash TokenMonitor/build.sh
```

一次生成 `Token查询.app` + `Token查询-1.10.dmg` + `Token查询-1.10.pkg`。需要 macOS 自带 Command Line Tools。

## 技术说明

- SwiftUI + Swift Charts，原生 macOS 应用
- Swift Package Manager 构建，**不需要完整 Xcode**
- 菜单栏常驻（`LSUIElement`），不占 Dock
- 兼容 macOS 14 及以上
- 网络请求失败自动重试一次（仅网络错误与 5xx），超时 15 秒

### 一个编译上的坑

Command Line Tools 自带的 macOS SDK 把 SwiftUI 的 `@State` 改成了宏，而宏实现只随完整 Xcode 分发。纯 CLT 环境下编译会报：

```
external macro implementation type 'SwiftUIMacros.StateMacro' could not be found
```

工程的 `LocalState.swift` 用可用的 `@StateObject` 实现了一份等价替代，用法与 `@State` 完全一致，规避了这个问题。**全项目一律用 `@LocalState`，不要改回 `@State`。**

### 另一个坑

菜单栏弹窗里的 `ScrollView` 如果只设 `maxHeight` 会塌缩成 0，把页签一起吞掉。`PanelView.contentScroll` 必须给固定高度。

### 凭据存储

`CredentialStore` 负责 API Key 的本地加密：

- 密钥派生：`HKDF-SHA256(IOPlatformUUID, salt) → 32 字节`
- 加密：`AES-GCM`，`sealedBox.combined` 直接 base64 存进 JSON
- 两个文件都是 600 权限。注意 `.atomic` 写盘是「写临时文件再改名」，新文件权限跟着 umask 走（通常 644），所以 `AppPaths.write` 必须在写完后再 `setAttributes` 一次，不能指望 write 的 options 带权限
- `credentials.vault.json` 存 salt 和种子来源。**如果这个文件被删而 `credentials.json` 还在，绝不能新建密钥** —— 那会静默生成一个解不开已存凭据的新密钥，用户只会看到「余额取不到」而完全不知道原因。代码里显式判断了这种情况并拒绝新建，宁可明确失败
- 本机读不到 `IOPlatformUUID` 时退化为随机密钥存本机文件（`seedSource: "file"`）。界面的说明文字读的是 vault 里**实际记的** `seedSource`，不能拿「现在能不能读到 UUID」去猜

## 已知限制

- **凭据存储是安全降级**：本机其他程序仍可解密（它同样读得到 `IOPlatformUUID`），这一点不如钥匙串。防住的是文件被拷走 / 云同步 / 备份 / 误发
- 换机器或换主板后需重新填入 API Key
- 未做 Apple 开发者签名与公证。从网上下载的副本首次打开会被 Gatekeeper 拦下：先试右键 →「打开」；新版 macOS 若仍然拦住，就去「系统设置 → 隐私与安全性」点「仍要打开」。这是未签名分发的必然代价
- 开机自启依赖系统服务注册，未签名 App 可能注册失败
- 轮询间隔低于 1 分钟可能触发服务端风控，默认 5 分钟
- 目前只支持 DeepSeek，其他厂商的余额接口格式不同，需要单独适配

## 自己构建

本仓库只含源码，**不含编译好的 App**。要自己用，需要 macOS 14 及以上 + 系统自带的 Command Line Tools（**不需要**完整 Xcode）：

```bash
bash build.sh
```

一次产出 `dist/` 下的 `Token查询.app`、`Token查询-1.10.dmg`、`Token查询-1.10.pkg`。App 是 ad-hoc 签名，首次打开需按上面「已知限制」里的说明放行一次。

程序不需要注册任何账号，所有数据只存在本机；DeepSeek 的 API Key 需要你自己到 [platform.deepseek.com/api_keys](https://platform.deepseek.com/api_keys) 申请。
